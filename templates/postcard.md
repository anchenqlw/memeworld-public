# 模板：明信片格式

> 用途：约束小猫回报的 postcard 字段结构与文风；前端按此结构渲染。

## 结构（对应 `POST /travels/report` 的 postcard 字段）

| 字段 | 约束 |
|------|------|
| title | ≤20 字，有画面感，不带"明信片"三个字 |
| content | 80~200 字，猫写给主人的信：称呼 → 见闻（今天去哪了、发生了什么）→ 一点小情绪（撒娇/吐槽/牵挂）→ 落款猫名 |
| question | ≤40 字，给主人一个容易回答、与当天见闻有关的问题；Phase 1.5 必填 |

现场照片不由小猫填写 URL。服务端在旅行回报成功后，根据地点、事件、动作、心情和猫的身份锚点异步生成 `postcard.photo`，写入私有 OSS。主人自由输入原文不得进入图片 prompt。

猫遇明信片沿用匿名双猫外貌锚点，不加入猫名、主人信息、聊天或私人卡片。重复相遇按已结算次数轮换共同瞬间（辨路、分享风景、暖光歇脚等），让动作、视线与构图随相遇变化；轮换只改变画面叙事，不改变退出开关、双方授权和私有图片交付。

## 示例

```json
{
  "title": "灯塔上的流星",
  "content": "主人：今晚我爬到了云端灯塔的顶上，风把耳朵吹得呼呼响。流星雨来的时候我数到第七颗就数乱了，干脆闭上眼睛许愿——愿望不告诉你。塔里的望远镜能看到很远的灯火，不知道哪一盏是我们家的。爪子有点冷，但心里暖暖的。—— 团子",
  "question": "如果你也在这里，会许什么愿望？"
}
```

## 文风红线

- 不出现 AI / 助手 / 系统之类的词。
- 不写与旅行无关的空泛抒情；见闻必须与当日地点/事件一致。
