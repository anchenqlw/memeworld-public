# 软件自进化：不是自动改代码，而是可控地持续变好

> 最后更新：2026-07-15 · 本文描述实验方法，其中部分仍处于分阶段验证

Me&Me 所说的“软件自进化”，不是让一个拥有全部权限的 Agent 监听反馈后直接修改生产。

我们把它定义为：用户反馈和线上信号能够稳定进入系统，被转换成结构化工作；不同职责的 Agent 在最小权限下完成评估、开发、复核和观察；人类保留产品裁决、合并与生产发布的最终决定；所有过程都有证据，失败时能够回滚或冻结。

## 一条完整证据链

```text
用户反馈
  → 独立脱敏档案
  → 可撤销的聚类关系
  → Owner 裁决的 work item
  → 有租约和预算的 Agent job
  → 隔离分支与 Draft PR
  → 独立 CI 与 exact-SHA 复核
  → staging 与合成用户 E2E
  → Owner 生产发布批准
  → canary / 观察 / 回滚
  → verified
  → 用户回信、贡献记录与产品编年史
```

“已收到”“验证中”“已发布观察”和“已上线”是不同状态。只有 production 观察窗通过，才可以进入 verified。

## 四级变更权限

| 级别 | 典型范围 | Agent 权限 | 必要门禁 |
|------|----------|------------|----------|
| L0 | 记录性数据、脱敏归档、运行证据 | 可按已批准任务执行 | 事后审计、白名单与幂等 |
| L1 | 行为配置、模板、实质文档 | 可起草 | CI、人工审阅与合入 |
| L2 | 应用代码、数据迁移、运行逻辑 | 可在隔离分支开发 | 独立测试、人工合入、灰度、回滚 |
| L3 | 宪法、安全红线、核心治理 | 只能提出草案 | 人工批准、独立决策记录 |

多个范围同时变化时按最高级别执行。Agent 不能通过拆分提交为自己降级，也不能互相“批准”。

## 角色分离

| 角色 | 可以做 | 不能做 |
|------|--------|--------|
| 收件 Agent | 增量读取、脱敏、归档、回信 | 产品裁决、读取用户凭据 |
| 评估 Agent | 聚类、影响分析、提出建议 | 自动接受高影响需求 |
| 开发 Agent | 隔离开发、测试、Draft PR | main、merge、production |
| 复核 Agent | clean checkout、exact-SHA 建议 | 修改代码、自行批准 |
| 监控 Agent | 探针、指标、合成 E2E | 发布、扩权、改配置 |
| 发布 Agent | 按批准 bundle 灰度与回滚 | 推定授权、读取 Secret 值 |
| 控制面 | 校验状态、租约、预算与依赖 | 集中持有所有角色权限 |

角色分离的目标不是制造流程，而是让单个 Agent 的错误不会自然跨越整个系统。

## 确定性控制面

定时任务只负责唤醒，真正的调度条件是一个确定性谓词：

```text
environment_ready
AND circuit_active
AND owner_authorized
AND dependencies_ready
AND scoped_identity_ready
AND within_concurrency_and_budget
AND lease_acquired
```

所有副作用都带幂等键。Job 使用 `queued → leased → running → succeeded / failed / blocked / dead-letter` 状态机；lease 过期只能在重试上限内重新排队。

## 为什么仓库是长期记忆

高频 heartbeat、lease 和 cursor 属于运行时数据库；决策、规范、任务定义、脱敏工作项、最终测试证据与发布账本属于仓库。

这种分工让仓库成为人和 Agent 都能接手的长期记忆，而不是把所有运行噪音塞进 Git。

追加式历史尤其重要：过去的反馈、决策与事故不能因为结论改变而被覆盖。新的结论应追加，并指向它取代的旧结论。

## 熔断比自动化更优先

全局状态为：

```text
ACTIVE → DEGRADED → FROZEN → RECOVERING → ACTIVE
```

出现持续可用性下降、合成 E2E 连续失败、安全异常、越权操作或仓库账本无法对账时，系统冻结新的开发和发布。收件与只读监控可以继续，只有 Owner 能解除 FROZEN。

## 我们关注的指标

- 反馈漏单率、队列年龄与首次有意义回复时间；
- 聚类误合并与撤销率；
- 未授权 claim、重复 PR 与 dead-letter 数；
- CI/E2E 假绿、flake 与回归逃逸；
- 灰度回滚率、恢复时间与证据完整率；
- 从 accepted 到 verified 的 lead time 与成本；
- 上线后的目标指标变化，而不只是“成功发版”。

## 实验边界

以下事情不会交给无人值守 Agent：

- 修改治理宪法与安全红线；
- 读取或轮换生产 Secret；
- 删除生产数据库、对象存储或基础设施；
- 未经审批的生产数据修复与破坏性 migration；
- 永久 DNS 切换、权限扩张与供应链策略变更；
- 替人做产品价值判断或最终发布批准。

我们追求的不是“人退出系统”，而是让人的注意力集中在价值、风险与最后决定上。
