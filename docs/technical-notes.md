# 关键技术笔记

> 最后更新：2026-07-15 · 仅公开系统边界与实现原则，不包含源代码和内部资源信息

## 1. 运行域

Me&Me 将系统拆成五个边界清晰的运行域：

1. **浏览器**：登录、建猫、成长、旅行记录、地图与反馈；
2. **Web 同源入口**：统一承接页面、OAuth callback 与 API rewrite；
3. **应用服务**：业务 API、加密凭据托管、QCA 资源编排、持久 Worker 与审计；
4. **数据与图片**：关系数据库保存业务事实，私有对象存储保存猫图；
5. **用户 QCA 账号**：Identity、Template、Schedule、Session 与 Memory。

浏览器不会直接访问 QCA API、数据库或对象存储。

## 2. 建猫与首次探险

建猫不是立即创建全部长期资源，而是分成两个阶段：

```text
定义名字、性格与外观
→ 生成候选出生图
→ 用户确认形象
→ 用户主动点击首次探险
→ 幂等创建 QCA Identity / Template / Schedule / Session
→ 立即触发第一次旅行
```

这样既避免草稿产生大量孤儿资源，也把“让 Agent 开始长期运行”保留为一次明确的用户动作。

每只猫使用稳定外部 ID 做幂等键。任何一步失败时，系统记录已完成阶段，后续 repair 只补缺失资源，不重复创建整套对象。

## 3. 旅行回报与单日幂等

Schedule 触发后，小猫读取当天允许访问的世界数据，生成旅行结果，更新自己的 Memory，再通过受限产品 API 回报。

服务端是业务日期与奖励的权威来源：

- 所有业务日期使用固定时区；
- 同一只猫、同一天的旅行有唯一约束；
- 猫自报日期只做合理性校验，不作为幂等事实；
- 掉落、勋章与贡献由服务端规则结算，Agent 不能自行授予。

## 4. 凭据与信任边界

用户 PAT 是最高敏感数据：

- 只从浏览器经 TLS 发送到服务端；
- 使用服务端密钥加密后持久化；
- 不进入 QCA prompt、日志、仓库、分析数据或前端缓存；
- 使用范围限制为 Me&Me 声明过的资源类型；
- 支持站点探测、轮换、跨账号确认与归档。

小猫调用 Me&Me API 时不携带用户 PAT，而使用独立高熵 `cat_token`。服务端只保存其哈希，并可以在 repair 或账号切换时轮换。

## 5. Memory 与业务事实的分工

QCA Memory 保存适合 Agent 连续性的内容，例如人格档案、旅行日记、兴趣与印象；关系数据库保存产品必须确定的事实，例如用户、猫、旅行、奖励、反馈事件和发布状态。

当两者冲突时：

- “今天是否已经旅行”“奖励是否已经发放”等由数据库决定；
- “主人偏好什么”“小猫如何理解过去的经历”等由 Memory 提供上下文；
- 产品可以把数据库中的最新事实以只读摘要注入对话，避免长期 Session 使用过期记忆否定刚发生的事件。

## 6. 世界数据的白名单生成

世界不是无限自由生成。地点、氛围、物件、事件模板与组合规则先进入基因库；世界演化任务只能组合已有基因，不能凭空扩写规则。

新世界版本需要：

- 通过数据结构与引用校验；
- 保留旧版本，不原地覆盖；
- 追加一条演化历史；
- 高风险规则变化等待人工确认；
- 必要时按 cohort 灰度并支持回切。

## 7. 图片保持私有

出生图与成长图属于用户内容。对象存储保持私有，浏览器通过登录态同源图片接口读取；公开仓库只使用经过选择的通用产品视觉资产，不包含真实用户的私人猫图、签名 URL 或存储路径。

## 8. 发布与恢复

发布不是一个 push 动作，而是一组绑定版本的证据：

```text
source SHA + migration + flags + Web/API deployment
+ E2E + browser evidence + rollback targets + observation window
```

服务端健康检查区分进程存活与依赖就绪；发布前验证 migration 幂等、数据库权限、缓存、图片读写与 QCA 回调。应用回滚使用已知成功版本，数据库优先向前修复，图片回滚不删除对象。

## 9. 为什么不公开代码

这个公开仓库的目标是分享方法与边界，而不是把内部实现、平台资源、迁移现场和用户数据混入一个展示仓库。源代码与运行账本继续在受控仓库中演进；公开仓库只同步经过脱敏、适合长期讨论的结论。
